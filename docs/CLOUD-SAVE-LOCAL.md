# 服务器存档与可选新对局自动上传（本地增量）

入口：**主页「统计数据」 → 服务器存档**。玩家可勾选统计（总览、策略、战斗累计、对局记录共享同一记录库）与干员调配（技能、模组、潜能/练度和皮肤）。不包含持有列表、自选编队、音量、逐干员语音语言、会话或正在进行的对局。

存档玩家名固定使用实际进入游戏时的玩家名，面板不可编辑；标题页未进入游戏时需先进入，不使用记忆名或其他备用身份。改用其他玩家名进入游戏后，面板及请求随当前身份更新。恢复密码为 **8–128字**，与玩家名一起识别存档；首次上传设置密码，以后更新必须使用同一密码。同名不同密码拒绝上传和读取，不覆盖。密码不保存到浏览器；提交后清空输入框。忘记密码没有找回入口。

- **默认不自动上传**。统计仍先存浏览器；手动上传先弹出与恢复同样的危险确认对话框，说明同名存档的所选组将被替换、不合并记录、本机数据不变。确认后才采集并上传；取消不发请求，服务器存档不变。未勾选组在服务器保留。
- 恢复先读取服务器，再确认，随后在浏览器保存恢复前数据，再替换所选组（不合并）。本机备份写失败则拒绝替换；局部写失败尽量回退，失败状态不会隐藏。
- 恢复前备份在本浏览器 `localStorage['sp.cloud.backup.latest']`，含原始键值及时间；只有最近一次。不要清除浏览器存储。该备份与原统计导出不同；需要人工取出 `values['sp.pref.stats']` 后可用现有统计导入，取出 loadout/skins 原值可恢复设置。备份同样占浏览器额度，额度不足会提示并停止恢复。
- 为避免修改使用中的设置，先离开房间再恢复。
- 现有部署使用 **HTTP，不提供传输加密**。必须使用不在其他网站复用的专用恢复密码。服务器存储随机盐的 scrypt 哈希（N=16384,r=8,p=1,32字节）；存档数据本身未加密，不是可信竞技成绩。统计可能含队友代号。

## 可选自动上传新对局

勾选「自动上传新对局记录」，输入原恢复密码并明确确认后，以当前实际进入身份验证已有服务器存档；不存在或密码错误则拒绝，须先用手动上传创建。「验证身份并恢复云设置」只验证原密码并读取既有设置，不开启上传、不重置启用时间、不上传历史。服务端保存开关及启用时间；刷新可凭本机令牌恢复，另一浏览器必须验证原密码，仅凭昵称不能恢复云设置或读取统计。

- 仅追加授权后**实际新写入本机**的结算或退出记录（包括仅列历史、不计成绩的退出），不发送旧历史、导入、恢复、迁移、已记录的重复推送或观战记录。重新连接的结果重放只写本机，不触发自动上传。
- 不依赖手动组勾选，不上传干员设置；服务器按记录ID去重，已存记录胜出，并共用本机记录正规化、1000条/30条完整记录/800000字符预算。超预算时按现有规则压缩/淘汰旧记录；未选干员设置保留。
- 密码只在请求时使用且提交后清空，不保存到浏览器或日志。本机localStorage保存限30天的随机授权令牌及有界待上传队列；服务器仅保存令牌哈希。令牌限定当前存档的读统计/自动追加/设置/撤销，不能替换手动存档组。刷新验证令牌后恢复服务器开关和启用时间；退出或换身份移除令牌、清空队列并请求撤销。HTTP未加密，令牌同样有被窃取风险；不要在不可信设备授权。
- 查看「总览、策略、战斗累计、对局记录」任一页时按需读取云统计并合并，不使用后台轮询。必须先验证密码或已有有效令牌；自动上传关闭也可读取。按ID合并，本机重复记录胜出、本机独有记录保留，不修改干员设置、不触发历史自动上传。先保存并读回本机备份；未来版本、损坏数据、容量或备份/写入失败时拒绝合并，不默默淘汰本机历史。
- 自动请求串行，最多32条等待记录；网络/存储暂时失败5秒、10秒重试，限流60秒后重试，最多重试2次。AUTH、格式、容量、队列满或重试耗尽则停止并要求重新授权。关闭会取消等待重试及发起中的请求；已经被服务器接受的请求不能撤销。成功时间仅取实际成功响应，失败不删除本机记录，也不会把待发送的旧记录带到新身份或新授权中。可手动上传处理遗漏记录（注意其替换所选组的既有语义）。
- 面板显示关闭、等待、上传、有限重试、暂停/错误与最后确认上传时间。完整UI、真实凭证与战斗验收由玩家完成。

## 服务器与持久化

`POST /api/cloud-save/upload`，JSON `{name,password,payload:{v:1,stats?,operators?}}`。
`POST /api/cloud-save/restore`，JSON `{name,password}`。密码不放 URL。
`POST /api/cloud-save/append`，JSON `{name,password,records:[…]}`，单次1–32条，不接受payload/干员组。须已有存档；复用相同来源限制、身份验证、限流、串行事务与原子持久化。
新增 `authorize {name,password,enabled?}` 签发作用域令牌并返回 `auto {enabled,enabledAt}`；省略enabled保持服务器设置。`state/read/settings/revoke {name,token,enabled?}` 均验证令牌；read仅返回统计。自动客户端 `append {name,token,records}` 强制开关开启且每条时间不早于启用时间。重启或重建保留设置、启用时间及令牌哈希。

存档目录由 `SP_CLOUD_SAVE_DIR` 指定，部署为 `/var/player-saves`，挂载外部命名卷 `stronghold-player-saves`；staging 使用独立卷 `stronghold-player-saves-staging`。不要使用 `docker compose down -v`、删除卷或全局 volume prune。重建镜像及服务保留外部卷。

请求限2,000,000字节、10秒读请求时间；统计至多1000记录/每局8玩家，原调配160条/潜能练度256条，递归深度和节点数有界。直接来源IP每分钟30次，所有地址（含LAN/loopback）都限速，不相信转发头；最多4个读入/排队请求，单个KDF/文件事务串行。注册与更新串行避免同名并发覆盖。私有目录700，文件600；文件名为玩家名SHA256，临时文件随机名，写入fsync → 原子rename → 目录fsync，不允许路径拼接玩家名。跨来源浏览器POST拒绝，不启用CORS。不记录密码或请求体。

`400 INVALID` 输入/版本/结构不符；`403 AUTH` 未找到或密码错误（相同提示）；`413 TOO_LARGE` 容量超限；`429 RATE` 操作过频；`500 STORAGE` 存储故障。网络超时不能证明上传成功，界面提示用恢复检查。

客户端战斗、八人/聊天/皮肤、可选莱茵及右侧伤害HUD保持原部署镜像，使用不可变小文件覆盖层；无素材、依赖或玩法批量替换。完整游戏/多设备/战斗验收由玩家完成。
